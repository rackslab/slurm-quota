# vortex testbed

Material to run the functional tests specified in [tests/specs](../../tests/specs/) on the `vortex` development cluster
deployed with FireHPC (see [devs/README.md](../README.md)).

- `vortex.adoc`: testbed profile, the values of the placeholders of the specification on vortex.
- `vtest`: runs a command on a cluster node as a given user, and appends the command, its output and its exit code to
  the evidence file of a test.
- `vweb.py`: helpers to drive the web dashboard with [Playwright](https://playwright.dev/python/) and save screenshots.
- `vreport.py`: generates the summary and the detailed results of a run, included in its PDF report.

## Setup

These steps complete the FireHPC deployment to meet the global prerequisites of the specification. They are not
persisted by FireHPC settings, run them again after each deployment.

1. Associate `user_a` with `account_b`, and synchronize associations:

   ```sh
   firehpc ssh admin.vortex -- sacctmgr -i add user bdennis account=acoustic
   firehpc ssh admin.vortex -- systemctl start slurm-quota-sync.service
   ```

1. Enable the periodic synchronization of associations:

   ```sh
   firehpc ssh admin.vortex -- systemctl enable --now slurm-quota-sync.timer
   ```

The restriction of slurm-quota admins to `admin_user` is set in FireHPC settings (`slurmquota_admins` in
`devs/firehpc/conf/vortex/group_vars/all.yml`).

All generated users have the same password, the default `ldap_user_password` of FireHPC `ldap` role.

## Migration tests

The tests of the REALLOCATE chapter require a database migrated from version 3. On vortex, it is prepared by downgrading
slurm-quota to the last version 3 release of the Rackslab `pkgs` repository, then upgrading to the development version
of the `devs` repository, which runs the database migration:

1. Stop `slurmctld` and the REST API, and move the current database aside.
1. Downgrade the packages on the admin node, for example
   `dnf downgrade slurm-quota-3.0.1-1.el9 slurm-quota-controller-3.0.1-1.el9 slurm-quota-web-3.0.1-1.el9`.
1. Start the REST API and `slurmctld`: version 3 creates a new database.
1. Note the current time as `<start>`, then submit jobs of several users on several accounts, with CPU and GPU, and
   optionally adjust consumption with the version 3 REST API (`PATCH /consumption/<user|account>/<name>/<resource>`).
1. Upgrade following [docs/upgrade-v3-to-v4.md](../../docs/upgrade-v3-to-v4.md), steps 1 and 2.
1. Run the tests with `--starttime <start>`.

The migration keeps a backup of the version 3 database next to the database (`slurm-quota-v3-backup-<date>.db`). To run
the tests again on the same data, without downgrading, stop the REST API, restore this backup as the database, run
`/usr/libexec/slurm-quota/slurm-quota-migrate`, and start the REST API. Add `--endtime` to the reallocation commands, to
exclude the jobs submitted after the migration.

## Running commands

Set the evidence directory and run commands with `vtest`, for example:

```sh
export VTEST_EVIDENCE=devs/reports/<date>-vortex/evidence
devs/testbed/vtest FT-SUBMIT-001 login bdennis 'sbatch -A biology -p standard -n 2 -t 10 --wrap "sleep 120"'
```

`vtest` reaches nodes over SSH with the key and proxy command of FireHPC, and keeps a master connection open for 30
minutes to speed up the next commands. With `-i`, standard input is forwarded to the command, for example a password for
`slurm-quota login --save`, and not recorded in the evidence.

## Web dashboard

The dashboard is not reachable from the workstation. Open an SSH tunnel to the admin node:

```sh
S=~/.local/state/firehpc/clusters/vortex/ssh
ssh -N -o ExitOnForwardFailure=yes -o UserKnownHostsFile=$S/known_hosts -i $S/id_rsa \
    -o 'ProxyCommand=/usr/bin/firehpc --remote <user>@<firehpc-host> remote proxy %h %p' \
    -L 127.0.0.1:8443:localhost:443 -l root admin.vortex.<namespace>
```

The dashboard is then available at `https://127.0.0.1:8443/quota/`, with the self-signed certificate of the cluster.

Install Playwright and Pillow, used to blur tokens in screenshots, in a virtual environment, using the Chromium of the
system:

```sh
python3 -m venv .venv
.venv/bin/pip install playwright pillow
```

Scripts importing `vweb` take screenshots in `VTEST_SCREENSHOTS`, and sign in with the password in `VTEST_PASSWORD`.
Fields holding secrets, such as new tokens, are hidden with blurring squares with the `hide` argument of `vweb.shot()`.

## Reports

The results of a run are kept in `devs/reports/<date>-vortex/`, which is not tracked in git: reports are published as
release artifacts.

- `results.txt`: status of each test, one line per test (`<id>|<status>|<notes>`). Notes may reference GitHub issues as
  `rackslab/slurm-quota#<number>`.
- `evidence/<id>.txt`: evidence recorded by `vtest`.
- `screenshots/<id>-<step>.png`: screenshots taken with `vweb.py`, with an `img` symbolic link to this directory for the
  PDF report.
- `report.adoc`: main document of the PDF report, with its title, author, revision, `:lang: en`, the values of the
  placeholders (copied from `vortex.adoc`), an introduction and the test environment. It includes `summary.adoc` and
  `details.adoc`, generated by `vreport.py`.

Generate the summary and the details, then build the PDF report with the Rackslab documents container, from the
repository root:

```sh
python3 devs/testbed/vreport.py devs/reports/<date>-vortex
podman run --rm -v "$PWD:/work" -w /work/devs/reports/<date>-vortex \
  containers.in.rackslab.io/communication/materials/documents:latest \
  rackslab-build-pdf --kind reports report.adoc
```

`vreport.py` copies the specification and the evidence of each test in `details.adoc`: the report keeps the
specification of the tests as run, and `rackslab-build-pdf` only stages AsciiDoc sources and images of the document
directory. Use `%autofit` listings for wide terminal output.

Publish the PDF report and a tarball of the sources of the run:

```sh
tar -C devs/reports --exclude=report.pdf --exclude=.rackslab-pdf-build --exclude=.ninja_log \
  -czf slurm-quota-functional-tests-<date>-vortex.tar.gz <date>-vortex
```
