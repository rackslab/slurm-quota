== Name

slurm-quota - manage Slurm CPU/GPU quota accounting, limits, and stats

== Synopsis

*slurm-quota* [*-h*] [*--debug* | *-q* | *--quiet*] [*--log-flags* <flag>]... [*--debug-flags* <flag>]... [*--version*] <command> [<args>...]

== Description

*slurm-quota* is a REST API client for the `slurm-quota-serve` HTTP service.
It manages CPU and GPU minute quotas for Slurm users and accounts, configures
quota and GPU charging settings, and displays consumption statistics.

== Global Options

*-h*, *--help*::
  Show help and exit.

*--debug*::
  Enable debug output.

*-q*, *--quiet*::
  Only print errors and warnings.

*--log-flags* <flag>::
  Component whose logs are enabled (repeatable; special value `ALL`). Default: `slurm_quota`.

*--debug-flags* <flag>::
  Component whose debug logs are enabled when *--debug* is used (repeatable; special value `ALL`). Default: `slurm_quota`.

*--version*::
  Show program version and exit.

== Commands

=== login

*slurm-quota login* [<username>] [*--save*]

Authenticate with LDAP and obtain a JWT from the HTTP service (`POST /login`).
Requires LDAP authentication enabled on `slurm-quota-serve`.

Options:

*<username>*::
  Optional LDAP username. Defaults to the current OS user when omitted.

*--save*::
  Save the token to `$XDG_CONFIG_HOME/slurm-quota/token` (default:
  `~/.config/slurm-quota/token`). Without this option, the token is printed to
  stdout.

Examples:

....
slurm-quota login
slurm-quota login bob
slurm-quota login --save
....

=== token

*slurm-quota token* [*--save*]

Show metadata about the current API authentication token (source, username,
type, scopes, expiration). The effective token is read from *SLURM_QUOTA_TOKEN*
when set, otherwise from `$XDG_CONFIG_HOME/slurm-quota/token`.

Options:

*--save*::
  Save the JWT from the *SLURM_QUOTA_TOKEN* environment variable to
  `$XDG_CONFIG_HOME/slurm-quota/token` for automatic use by other subcommands.

*slurm-quota token create* <name> *--scope* <scope> [*--scope* <scope>]... [*--duration* <days>]

Create an application token for scripts and integrations, with the given
scopes among the scopes available for the role of the user: `stats:read:own`,
`stats:read:managed`, `stats:read:all`, `quotas:read`, `quotas:write`,
`comments:write`, `roles:read` and `roles:write`. The token is printed on
stdout, its identifier and expiration date on stderr. It cannot be displayed
again. Requires a user token, application tokens cannot create application
tokens.

*<name>*::
  Name of the token, unique among the active tokens of the user.

*--scope* <scope>::
  Scope granted to the token. Repeat the option to grant multiple scopes.

*--duration* <days>::
  Token validity in days. Defaults to `jwt.app_duration` of the service, and
  cannot exceed `jwt.app_max_duration`.

*slurm-quota token list* [*--user* <username> | *--all*]

List application tokens of the current user, with their identifier, name,
scopes, creation and expiration dates, and status (active, expired or revoked).

*--user* <username>::
  List application tokens of this user (admin only).

*--all*::
  List application tokens of all users (admin only).

*slurm-quota token revoke* <id>

Revoke an application token by its identifier. Users can revoke their own
tokens, admins can revoke any token.

Examples:

....
slurm-quota token
export SLURM_QUOTA_TOKEN=$(sudo slurm-quota-token alice)
slurm-quota token --save
slurm-quota token create monitoring --scope stats:read:all --duration 180 > monitoring.token
slurm-quota token list
slurm-quota token revoke 3f2a9c4e8b7d41c6a0e5d9b8c7f6e5d4
....

=== stats

*slurm-quota stats* [<username>] [*--user* <username>] [*--account* <account>] [*--all*] [*--breakdown* | *--no-breakdown*] [*--comments*] [*--hours* | *--seconds*]

Display quota statistics (consumed, preallocated, quota, and status) for users
and/or accounts using the HTTP service (`/stats`).

By default, the consumption of the selected user is broken down by account
below the user row, and the consumption of the selected account is broken down
by user below the account row. This breakdown is informational, quotas are
defined for users and accounts.

Options:

*<username>*::
  Optional positional user selector.

*--user* <username>::
  User selector equivalent to positional `<username>`.

*--account* <account>::
  Account selector.

*--all*::
  Show all users/accounts (no username filter).

*--breakdown*::
  Break down the consumption of users by account and the consumption of
  accounts by user. This is the default for a single user or account. With
  *--all*, both user and account rows are broken down.

*--no-breakdown*::
  Do not break down the consumption of the selected user or account.

*--comments*::
  Display the comment of users and accounts, when defined (see *comments*), on
  a line starting with `#` below their row.

*--hours*::
  Display values in hours instead of minutes.

*--seconds*::
  Display values in seconds instead of minutes.

Notes:

- Positional `<username>` and `--user` are mutually exclusive.
- User selection (`<username>` or `--user`) and `--account` are mutually exclusive.
- `--hours` and `--seconds` are mutually exclusive.
- `--breakdown` and `--no-breakdown` are mutually exclusive.
- If no selector is provided, the current OS user is used.

Examples:

....
slurm-quota stats
slurm-quota stats alice
slurm-quota stats --account hpc
slurm-quota stats --all --hours
slurm-quota stats --all --breakdown
slurm-quota stats --all --comments
slurm-quota stats alice --seconds
slurm-quota stats alice --no-breakdown
....

=== role

*slurm-quota role* *show* | *list* | *grant* <operator|manager> <username> | *revoke* <operator|manager> <username> | *managers* *list* <username> | *managers* *add* <username> <account> | *managers* *remove* <username> <account>

Show or manage REST API user roles. Requires a saved JWT token or
`SLURM_QUOTA_TOKEN`.

Subcommands:

*show*::
  Display the current caller username and role.

*list*::
  List all users with their role (admin only).

*grant* <operator|manager> <username>::
  Grant operator or manager role to a user (admin only).

*revoke* <operator|manager> <username>::
  Revoke operator or manager role from a user (admin only).

*managers* *list* <username>::
  List accounts assigned to a manager (admin only).

*managers* *add* <username> <account>::
  Assign an account to a manager (admin only).

*managers* *remove* <username> <account>::
  Remove an account from a manager (admin only).

Examples:

....
slurm-quota role show
slurm-quota role list
slurm-quota role grant operator bob
slurm-quota role grant manager bob
slurm-quota role revoke operator bob
slurm-quota role managers list bob
slurm-quota role managers add bob hpc
slurm-quota role managers remove bob hpc
....

=== adjust

*slurm-quota adjust* *--user* <username> *--account* <account> (*--cpu* | *--gpu*) (*--minutes* <signed_int> | *--hours* <signed_int> | *--seconds* <signed_int>) [*--reason* <text> [*--no-save-comment*]]

Adjust consumed CPU/GPU time of one user on one account. Consumption is recorded
per user/account pair: the adjustment changes both the user total and the account
total.
Requires a saved JWT token or `SLURM_QUOTA_TOKEN`, and operator or admin role.

Options:

*--user* <username>::
  Target user (required).

*--account* <account>::
  Target account (required).

*--cpu*::
  Adjust consumed CPU minutes.

*--gpu*::
  Adjust consumed GPU minutes.

*--minutes* <signed_int>::
  Signed delta in minutes, must include `+` or `-` (example: `+30`, `-120`).

*--hours* <signed_int>::
  Signed delta in hours, must include `+` or `-`.

*--seconds* <signed_int>::
  Signed delta in seconds, must include `+` or `-`. The new consumed total is
  then reported in seconds instead of whole minutes.

*--reason* <text>::
  Reason of the adjustment, recorded in the service audit logs. The reason is
  also saved in the comments of both the user and the account (see
  *comments*), after a ` | ` separator when a comment is already defined,
  unless *--no-save-comment* is given.

*--no-save-comment*::
  Do not save the reason in the comments of the user and the account.

Notes:

- Negative adjustments are clamped at zero (consumed time of the user/account pair never becomes negative).
- Both the user and the account must already be known in the database.

Examples:

....
slurm-quota adjust --user alice --account projX --cpu --minutes=+30
slurm-quota adjust --user alice --account projX --gpu --hours=-1
slurm-quota adjust --user alice --account projX --cpu --seconds=-45
....

*--no-save-comment*::
  Do not save the reason in the comment of the user.

Example:

....
slurm-quota user-quota alice 50000

=== comments

*slurm-quota comments* (*--user* <username> | *--account* <account>) (<comment> | *--clear*)

Set the free text comment of a user or an account, or remove it with *--clear*.
The comment must be a single line of at most 1000 characters. It is displayed
by the *stats* command with *--comments* and in the web dashboard to everyone
who can see the user or the account. The user or account is created in the
database with default quotas when missing. Requires a saved JWT token or
`SLURM_QUOTA_TOKEN`, and operator or admin role.

Options:

*--user* <username>::
  Set the comment of this user.

*--account* <account>::
  Set the comment of this account.

*--clear*::
  Remove the comment.

Notes:

- `--user` and `--account` are mutually exclusive, one is required.
- `<comment>` and `--clear` are mutually exclusive, one is required.

Examples:

....
slurm-quota comments --user alice "PhD student, thesis until 2027"
slurm-quota comments --account projX "Granted by allocation committee 2026-09"
slurm-quota comments --account projX --clear
....

=== gpu-factors

*slurm-quota gpu-factors*

Show configured GPU charging factors. Requires a saved API token or
`SLURM_QUOTA_TOKEN` (operator or admin role).

=== set-gpu-factor

*slurm-quota set-gpu-factor* <gpu_type> <factor>

Set GPU charging factor for a GPU type (`default` is accepted as fallback type). Argument _factor_ must be a positive float (> 0).
Requires a saved API token or `SLURM_QUOTA_TOKEN` (operator or admin role).

Example:

....
slurm-quota set-gpu-factor h100 0.5
....

=== default-quotas

*slurm-quota default-quotas*

Show default quotas used for newly auto-created users/accounts.
Requires a saved API token or `SLURM_QUOTA_TOKEN` (operator or admin role).


=== set-default-quotas

*slurm-quota set-default-quotas* [*--user-cpu* <minutes>] [*--user-gpu* <minutes>] [*--account-cpu* <minutes>] [*--account-gpu* <minutes>]

Set one or more default quotas for newly auto-created users/accounts.
At least one option is required at runtime. Argument _minutes_ must be a positive integer or `-1` means unlimited.
Requires a saved API token or `SLURM_QUOTA_TOKEN` (operator or admin role).

Example:

....
slurm-quota set-default-quotas --user-cpu 50000 --account-cpu 200000
....

== Environment

*SLURM_QUOTA_URL*::
  Base URL used by CLI subcommands that query the HTTP API (`stats`, `login`,
  quota management, and related commands).
  Default: `http://127.0.0.1:9911/`

*SLURM_QUOTA_CA_CERT*::
  Path to a CA certificate file used to verify the REST API TLS certificate when
  `SLURM_QUOTA_URL` uses `https://` and the certificate is not trusted by the
  system default store.

*SLURM_QUOTA_TOKEN*::
  JWT for HTTP API authentication. When set, takes precedence over the token
  file saved by `login --save` or `token --save`.

*XDG_CONFIG_HOME*::
  Base directory for user-specific configuration. The token saved by `login` is
  stored in `$XDG_CONFIG_HOME/slurm-quota/token` (default:
  `~/.config/slurm-quota/token`).

*NO_COLOR*::
  If set, disables colored status bars in `stats` output.

== Files

`$XDG_CONFIG_HOME/slurm-quota/token`::
  JWT saved by `login --save` or `token --save` for HTTP API authentication
  (default: `~/.config/slurm-quota/token`).

== Exit Status

*0*::
  Success.

*1*::
  Runtime/permission/operational error, or no subcommand provided.

*2*::
  Command-line parsing error (for example, mutually exclusive options used together).
